Plataforma de programação com IA. Tema escuro centrado no desenvolvedor.

Tema visual e atmosfera

O site do OpenCode encarna uma estética nativa do terminal, com a monoespaçada em primeiro lugar, que reflete sua identidade de agente de programação com IA open source. Todo o sistema visual é construído sobre um contraste austero de escuro sobre claro, usando um fundo quase preto (#201d1d) com texto off-white quente (#fdfcfc). Não é um tema escuro genérico — é um escuro quente, levemente marrom-avermelhado, que parece um emulador de terminal sofisticado e não uma IDE fria. O fundo quente tanto nos escuros quanto nos claros (repare no sutil canal vermelho de #201d1d — rgb(32, 29, 29)) cria uma qualidade coesa, de coisa usada.

A Berkeley Mono é a única fonte, estabelecendo uma identidade monoespaçada sem desculpas. Todo elemento — títulos, texto de corpo, botões, navegação — usa essa mesma família, criando uma filosofia unificada de "tudo é código". O título em 38px negrito, com altura de linha de 1.50, é generoso e legível, enquanto o texto de corpo em 16px com peso 500 oferece um peso de leitura um pouco mais pesado que o normal, que melhora a legibilidade na tela. A grade monoespaçada impõe naturalmente alinhamento e ritmo ao layout.

O sistema de cores é deliberadamente mínimo. A paleta principal tem só três tons funcionais: o quase preto quente (#201d1d), um cinza quente médio (#9a9898) e um off-white claro (#fdfcfc). As cores semânticas vêm da paleta do Apple HIG — destaque azul (#007aff), vermelho de perigo (#ff3b30), verde de sucesso (#30d158), laranja de alerta (#ff9f0a) —, dando à interface cores de sinalização familiares e confiáveis sem acrescentar complexidade de marca. As bordas usam uma transparência quente e sutil (rgba(15, 0, 0, 0.12)) que se liga ao fundo quente de todo o sistema.

Características principais:

  • Berkeley Mono como única fonte — monoespaçada em todo lugar, sem vozes sem serifa ou serifadas
  • Quase preto quente como primária (#201d1d), com fundo marrom-avermelhado, não preto puro
  • Texto off-white (#fdfcfc) com tom quente, não branco puro
  • Border-radius mínimo de 4px em todo lugar — cantos vivos e utilitários
  • Sistema de espaçamento com base de 8px, chegando a 96px
  • Cores semânticas inspiradas no Apple HIG (azul, vermelho, verde, laranja)
  • Bordas quentes transparentes usando rgba(15, 0, 0, 0.12)
  • Campo de e-mail com padding generoso de 20px e raio de 6px — o raio de componente mais generoso
  • Uma única variante de botão: fundo escuro, texto claro, padding vertical justo (4px 20px)
  • Links sublinhados como estilo padrão, reforçando a identidade centrada no texto

Princípios

  • Uma fonte, uma voz: a Berkeley Mono é usada com exclusividade. Não há variação tipográfica entre display, corpo e código — tudo fala no mesmo registro monoespaçado. A hierarquia é obtida só pelo tamanho e pelo peso.
  • Peso como hierarquia: 700 nos títulos, 500 em elementos interativos/ênfase média, 400 no texto de corpo. Três níveis de peso criam toda a hierarquia.
  • Altura de linha generosa: 1.50 como altura de linha padrão dá espaço para o texto respirar dentro da grade monoespaçada. A altura relaxada de 2.00 nas legendas cria uma separação visual clara.
  • Justo para interação: os elementos interativos (abas, rótulos compactos) usam altura de linha 1.00, para alvos clicáveis densos.

Princípios de layout

Sistema de espaçamento

  • Unidade base: 8px
  • Escala fina: 1px, 2px, 4px (abaixo de 8px, para bordas e microajustes)
  • Escala padrão: 8px, 12px, 16px, 20px, 24px
  • Escala estendida: 32px, 40px, 48px, 64px, 80px, 96px
  • O sistema segue uma grade limpa de 4/8px, com duplicação consistente

Grid e contêiner

  • Largura máxima do conteúdo: aproximadamente 800-900px (estreita, otimizada para leitura)
  • Layout de coluna única como padrão principal
  • Conteúdo centralizado com margens horizontais generosas
  • Seção hero: elemento de terminal escuro em largura total
  • Seções de recursos: blocos de texto em coluna única
  • Rodapé: grade de links em várias colunas

Filosofia do espaço em branco

  • Ritmo monoespaçado: a largura fixa da Berkeley Mono cria uma grade vertical natural. As alturas de linha de 1.50 e 2.00 mantêm um ritmo consistente.
  • Estreito e focado: o conteúdo fica restrito a uma coluna estreita, criando margens laterais generosas que concentram a atenção no texto.
  • Seções pelo espaçamento: sem divisores decorativos. As seções são separadas por espaçamento vertical generoso (48-96px), e não por bordas ou mudanças de fundo.

Escala de raios de borda

  • Micro (4px): padrão para todos os elementos — botões, contêineres, badges
  • Campo (6px): os campos de formulário ganham um pouco mais de arredondamento
  • O sistema inteiro usa só dois valores de raio, reforçando a estética utilitária

Filosofia das sombras: o sistema de profundidade do OpenCode é intencionalmente plano. Não há box-shadows nos tokens extraídos — nenhum valor de sombra foi detectado. A profundidade é comunicada exclusivamente por tratamentos de borda e mudanças de cor de fundo. Essa planicidade é coerente com a estética de terminal: terminais não têm sombras, e o OpenCode também não. Os três níveis de borda (quente transparente, indicador de aba, contorno sólido) criam hierarquia visual suficiente sem nenhuma ilusão de elevação.

Profundidade decorativa

  • Mudanças de cor de fundo entre #201d1d e #302c2c criam uma diferenciação sutil de superfície
  • Bordas transparentes a 12% de opacidade dão uma estrutura quase invisível
  • O toque avermelhado quente nas cores de borda (rgba(15, 0, 0, 0.12)) liga as bordas à paleta escura quente
  • Sem gradientes, sem desfoques, sem efeitos ambientes — pura estética plana de terminal

Interação e movimento

Estados de hover

  • Links: mudança de cor do padrão para o azul de destaque (#007aff) ou mudança no estilo do sublinhado
  • Botões: leve clareamento do fundo ou ênfase na borda
  • O azul de destaque oferece uma sequência de hover em três etapas: #007aff → #0056b3 → #004085 (padrão → hover → ativo)
  • Vermelho de perigo: #ff3b30 → #d70015 → #a50011
  • Laranja de alerta: #ff9f0a → #cc7f08 → #995f06

Estados de foco

  • Foco baseado em borda: aumento da opacidade da borda ou cor de borda sólida
  • Sem anéis de foco baseados em sombra — coerente com a estética plana e sem sombras
  • O foco de teclado provavelmente usa contorno ou mudança da cor da borda para o azul de destaque

Transições

  • Transições mínimas — interfaces inspiradas no terminal preferem mudanças de estado instantâneas
  • Transições de cor: 100-150ms para um feedback de estado sutil
  • Sem animações de escala, rotação ou transformações complexas

Guia de iteração

  1. A Berkeley Mono é a única fonte — nunca introduza uma segunda. Tamanho e peso criam toda a hierarquia.
  2. Mantenha as superfícies planas: sem sombras, sem gradientes, sem efeitos de desfoque. Use só bordas e mudanças de fundo.
  3. O fundo quente importa: use #201d1d, não #000000; use #fdfcfc, não #ffffff. O calor avermelhado é sutil, mas essencial.
  4. O border-radius é 4px em todo lugar, exceto nos campos (6px). Nunca use pílulas arredondadas ou raios grandes.
  5. As cores semânticas seguem o Apple HIG: azul #007aff, vermelho #ff3b30, verde #30d158, laranja #ff9f0a. Cada uma tem variantes escurecidas de hover e ativo.
  6. Interação em três etapas: padrão → hover (escurecido) → ativo (bem escurecido) em todas as cores semânticas.
  7. As bordas usam rgba(15, 0, 0, 0.12) — um escuro transparente quente, não cinza neutro. Isso liga as bordas à paleta quente.
  8. O espaçamento segue uma grade de 8px: 8, 16, 24, 32, 40, 48, 64, 80, 96px. Use 4px só para ajustes finos.
