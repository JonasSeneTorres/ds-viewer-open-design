Plataforma centrada em código. Densidade funcional, precisão de azul sobre branco, fundações do Primer.

Tema visual e atmosfera

A superfície do GitHub é projetada, não decorada. Cada pixel anuncia uma postura: esta é uma ferramenta para quem se importa com diffs, builds e pull requests. O fundo da página é um #ffffff limpo (claro) ou #0d1117 (escuro), com o conteúdo organizado em painéis retangulares densos, separados por bordas finíssimas em vez de espaço negativo. A densidade de informação é a marca — linhas de listas, linhas de código, cabeçalhos de repositórios e cards de notificação ficam todos bem juntos, para que um usuário avançado percorra cem itens sem rolar a página.

Os destaques característicos são o azul do Primer (#0969da) para links e ações principais e o verde do GitHub (#1a7f37) para estados de merge, sucesso e o próprio botão de merge. Ambos parecem um pouco mais apagados que os azuis e verdes de produtos de consumo — saturados o bastante para se destacar contra o texto cinza denso, contidos o bastante para sumir no fundo quando vários aparecem na mesma viewport.

A tipografia usa a pilha system-ui em todo o produto, para que o texto seja renderizado com nitidez em qualquer sistema operacional, combinada com SFMono / Menlo / Consolas para código. Não há fonte de display editorial; a voz do GitHub é a voz do sistema que você já está usando.

Características principais:

  • Tela de branco verdadeiro (#ffffff) ou preto-azulado profundo (#0d1117) — sem calor, sem tingimento
  • Bordas cinza finíssimas (#d0d7de) definem todo painel e quadro
  • Azul do Primer (#0969da) para links/ações principais; verde do GitHub (#1a7f37) para sucesso/merge
  • system-ui no texto; SFMono no código — nenhuma fonte própria
  • Linhas de listas densas, com padding mínimo; espaço em branco é raro
  • Iconografia Octicon em 16px / 24px — traço único, geométrica, consistente
  • Badges de status em formato de pílula com semântica de cor forte

Princípios

  • Corpo em 14px, não 16px: a densidade do texto do GitHub é sua identidade. O produto é lido em 14px para caber mais linhas numa viewport.
  • Peso binário: 400 para tudo por padrão; 600 para títulos e ênfase. Nada de 500, nada de 700.
  • Sempre fontes do sistema: nunca carregue uma webfont para a moldura — o texto precisa aparecer na hora, mesmo em conexões lentas.

Labels (tags em issues/PRs)

  • Padding: 0 7px
  • Raio: 9999px
  • Fonte: 12px / 500
  • Fundo e texto são programáticos (cor do label → texto calculado para contraste).

Espaçamento e layout

  • Unidade base: 4px. Escala de espaçamento: 4, 8, 12, 16, 24, 32, 40, 48.
  • Largura máxima da página: 1280px (Container-xl).
  • Barra lateral: 296px no desktop, recolhe abaixo de 1012px.
  • Padding das linhas: 16px na horizontal, 12px na vertical (as listas são densas por definição).

Movimento

  • Duração: 80ms no hover; 200ms ao abrir menus/popovers.
  • Easing: ease-out ao abrir, ease-in ao fechar.
  • Evitado: animação no carregamento da página, parallax, microinterações persistentes. As coisas aparecem; não fazem apresentação.

Limites de uso

  • Mantenha juntas as listas densas, as caixas com borda e a tipografia do sistema; botões verdes isolados não bastam para criar uma superfície de produto com cara de GitHub.
  • Use verde para ações construtivas no repositório, azul para links e foco, e vermelho/roxo/cinza só para estados de issues, PRs e workflows.
  • Prefira moldura discreta, bordas explícitas e espaçamento compacto a sombras decorativas ou cards grandes no estilo de marketing.
